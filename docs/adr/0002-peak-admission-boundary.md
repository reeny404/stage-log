# ADR 0002: 피크 이벤트의 공개 셸과 개인 입장 경계

- 상태: Accepted
- 날짜: 2026-09-15

## Context

콘서트·시상식 이벤트는 오픈 직후 짧은 시간에 읽기와 쓰기가 함께 증가한다. 모든 요청을 개인화된 동적 렌더링으로 처리하면 공개 일정조차 입장 API의 장애에 영향을 받는다. 반대로 포트폴리오 프로젝트에는 실제 대규모 이용자가 없으므로 운영 규모를 주장할 근거가 없다.

## Decision

- 이벤트 제목, 일정, 규칙, 드롭 목록은 빌드 시 생성 가능한 Server Component 셸로 제공한다.
- 개인 입장만 작은 Client Component에서 동적 API를 호출한다.
- 최초 입장 요청에는 idempotency key를 보내고 대기 상태 조회와 분리한다.
- 정상, 피크, 의존성 장애 계약을 `/api/demo/*`에서 재현한다.
- 데모 API는 실제 분산 대기열이 아닌 stateless simulation임을 UI와 README에 명시한다.
- 읽기와 쓰기 부하 시나리오는 k6에서 별도 태그로 측정한다.

## Consequences

- 개인 입장 API가 실패해도 공개 이벤트 정보는 계속 읽을 수 있다.
- UI에서 대기·입장·안전한 재시도를 반복해서 검증할 수 있다.
- 부하 테스트 수치는 특정 테스트 환경의 결과일 뿐 실제 사용자 처리량이 아니다.
- 실제 서비스 전환 시 서명된 입장 토큰, 외부 대기열, 영속 idempotency 저장소, 봇 방어가 추가로 필요하다.
